# skill-class-observe-eval 课堂观察评课技能

> 面向中小学教研场景的专业评课技能。基于听课记录、课堂录音纪要或教学录像描述，生成结构化评课报告（**完全版与简版均输出 Markdown + 排版规范的专业 Word 文档**，另附**议课组织方案**）。Word 为 A4 / 深蓝主题 / 斑马纹表格，可直接打印存档。

## 方法论框架：五层分职

本技能由《问课：智慧课堂教研指南》（胡小勇 主编，2026）为方法论主体，融合陈大伟《观课议课与教师成长》的评课理念，按五个层各司其职：

| 层 | 定什么 | 承载构件 | 来源 |
|----|--------|----------|------|
| ① 理念层 | 全篇语气与议课伦理 | 成长至上 / 以人为本 / 同在共行 / 以学论教 / 处境敏感 / 从批评走向建设 + 「深度理解」总标尺 | 陈大伟 + 《问课》第1章 |
| ② 观察层 | 取什么证 | 三维十三点（学生学习5 / 教师教学5 / 教与学关联3）+ 课堂思维观察五证据 | 陈大伟（精简）+ 《问课》第1章 |
| ③ 分析层 | 怎么分析透 | WISE 四层透视（结构W→行为I→策略S→成效E）+ 循证深度解读四视角 | 《问课》第2、8章 |
| ④ 议课层 | 怎么问 | 教研真问题判定 + 差异化发问六类型 + 句式库 + 发问自查表 | 《问课》第7章 |
| ⑤ 成果层 | 怎么沉淀 | AIED 四阶闭环 + 四类证据源 + 三角互证 + 教研成果提炼表 | 《问课》第3、9章 |

**核心主张**：好课的特征不变量是深度理解——它需要被设计、被激发、被看见、被证明。警惕「热闹≠深度、讲得多≠学得深、活动多≠思维多」三个常见误区（报告中称「三个常见误区核查」）。

**关于 CREATE 六维模型**：原版本采用的 CREATE 六维检核已整体撤出评课流程（科学性 + 实效性两方面均不成立），其设计要素检核功能由 ③分析层的 S 层「课堂策略」（教学设计 / 评价反馈两策略）承接，且更细、每阶段附带「意图错位」诊断。详见 `SKILL.md` 第 1.2 节。

**关于评分**：本技能**不使用任何分数、等级、排名**。成效判级采用「一率三度」的质性三档（充分 / 部分 / 未见），每档必须紧跟可观察证据。

## 功能特性

- **输入预处理**：录音纪要三支路处理（**显式发言人标签映射／隐式点名切分／降级清洗**，含角色置信度与课堂话语分析）、转写术语还原、输入质量三级评估与降级策略（不足时输出《观察提问清单》而非硬编报告）
- **🆕 课标核心素养对齐（v3.3.0）**：义教 2022 版 / 高中 2017 版 2020 修订双版本，覆盖小学 1-6／初中 7-9／高中 10-12 学段段位，全学科素养逐字清单 + 11 科「素养→课堂可观察表现」+ 单课时覆盖审计；**v3.3.2 起配套课标条目定位卡，报告中不再出现「待核实」半成品**
- **🆕 学科评课专家标准卡（v3.3.0）**：按各学科课标研制/修订组组长及核心成员的公开论述规划；领域层（人文「基本—单元—内容」／理工「老—新—疑难」／跨学科「问题驱动」／艺体劳另设）→ 学科层八字段卡 → 学段层；首批物理、信息科技、语文、数学四科完整卡；**v3.3.1 新增第二批 7 科完整卡**（化学／生物学／科学／英语／道德与法治／历史／地理，见 `discipline_cards_batch2.md`）
- **🆕 发言人区分与课堂话语分析（v3.3.0）**：兼容 6 类输入格式；角色映射表带置信度；话轮结构 IRF、学生参与画像、原问归属、观点碰撞追踪、齐答识别、学科话语观察点；隐私脱敏与降级纪律
- **课型分流**：新授 / 练习 / 复习三类课型有专属教研评估表与环节优化方法库；其他课型使用通用 WISE 标尺
- **三维十三点观察取证**：学生学习（核心）/ 教师教学 / 教与学的关联，每点要求现象白描 + 分析评价
- **课堂思维观察五证据**：提问质量、表达逻辑、观点碰撞、迁移应用、反思习惯——"重思维培养"类结论必须落到可观察证据；报告附录 A 按「观察到的实例 / 分析评价」分列呈现
- **WISE 四层透视**：结构 → 行为 → 策略 → 成效，主张"结构决定行为、行为体现策略、策略影响效果"
- **意图错位诊断**：六大策略逐项追问"这一步究竟想达成什么"，识别"名实不符"（如号称"思维激发"实则仅流程推进）
- **三个常见误区核查**：亮点定级前过筛，防止把「气氛活跃/讲得透彻/活动丰富」等「看着好、其实没学到」的情况误判为教学亮点
- **差异化发问设计**：六类型发问（场景/精准/适配/主体/建设性/理论）+ 证据前置句式 + "问题+1"原则，用于议课环节
- **结论前置的报告结构**：一句话总评 + 一页速览（三亮点 + 三建议）打头；正文只保留 3 张分析表（这节课是怎么走的 / 六个维度看这节课 / 学生学到了什么）；亮点与生长点用卡片呈现；取证表下沉附录备查
- **三份交付物**：完全版报告（Markdown + Word）+ 简版简报（Markdown + Word）+ 议课组织方案
- **专业 Word 排版**：A4 纵向、深蓝标题体系、表头深蓝底白字（跨页自动重复）、数据行斑马纹、引用块左竖线+底色、页码域自动更新
- **反例黑名单**：20 条语气/方法论/角色禁区 + 18 项输出质量自检清单

## 快速使用

1. 将整个目录复制到技能目录（如 `~/.workbuddy/skills/class-observe-eval`）
2. 在对话中说"评课"并粘贴听课记录 / 指定知识库中的听课文档 / 上传课堂录音纪要
3. 技能自动执行：输入质量评估 → 背景与课型确认 → 观察取证 → WISE 四层透视 → 常见误区核查与亮点/生长点 → 生成完全版 + 简版 + 议课组织方案 + 专业排版 Word（完全版与简版均转换）

### Word 转换脚本独立使用

```bash
python3 scripts/md2docx_report.py 报告.md 报告.docx
# 依赖：python-docx（pip install python-docx）
```
